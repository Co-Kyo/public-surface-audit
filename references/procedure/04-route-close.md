# 步骤 04 · 路由与收口：问题落到该落的地方，门给凭据

> 一条发现只去一个地方，且必须当场定下是改、是删、还是升成待办——挂着的发现等于没被发现。

**输入**：`03-adjudication.md`。
**产物**：裁决表"去向"列填满＋修复（或修复方案）＋同目录 `04-close.md`（收口记录，含**门凭据**一句话）。

## 做什么

1. **按类型路由**，一条发现只去一处，处置只有三种形态：**改／删／升级为待办**。

| 发现类型 | 去向 | 处置形态 |
|---|---|---|
| 文案本身要改（句子该改） | 呈报作者批 → 批了才改 → 改完复审受影响批次 | 改 |
| 属于"这条信息根本不该出门" | 删，不是改写——不做合规化处理 | 删 |
| 工具承诺句没有测试或构建期检查背书 | 缺口清单：补门 或 撤句，**二选一，不许挂着** | 改／升级为待办 |
| 实际行为与文档不符 | issue 清单：修实现，或修文档 | 升级为待办 |
| 判据本身有分歧（宪章没覆盖） | **停下问作者**——本程序无权自造规则 | 升级为待办（等人拍） |
| 词表召回误报，同类两轮以上 | 改 `scripts/redline-check.mjs` 规则，或记一条待办 | 升级为待办 |
| 只有实跑才暴露（读文本发现不了） | 标注出来，不在本程序处置 | 升级为待办 |

2. **收口**。作者批改写方案 → 改完 → 受影响批次复审 → 全部批次 PASS → 写 `04-close.md` 并记门凭据：
   "本轮（{YYYY-MM-DD}-{slug}）公开面审计：各通道各批 PASS，可发布。"
3. **门凭据只写在收口这一刻**，且必须能指到 `03-adjudication.md` 的逐条证据——指不到就不算凭据。
4. **过程产物可删，记忆留下**：`.audit/rounds/{YYYY-MM-DD}-{slug}/` 跑完即可删——收口记录已归档，记录在就行。中断没跑完的，先更新 `STATE.md` 再走。`.audit/graphify-out/`、`claims.json`、`verdicts.json` 是跨轮记忆，留着；若本轮跑过 `graphify update`，确认 `graph-audit reconcile` 已把审计层贴回图上。
5. **涉及 push／tag／publish**：停在发布门前，本程序不执行发布。

## 什么时候本程序判为失败

- **已知违规没被逮住**（负向验证不过）→ 判据或取证包有洞，回步骤 00 复盘，不许直接补审同一批。
- **主持者未逐条核对就出裁决** → 本轮作废重来。
- **某条 FAIL 的去向列空着，或处置停在"二选一"没选** → 收口无效，门凭据不许写。

## 检查点

- 每条"成立"都有去向，且只有一个？
- 承诺句缺口是真选了"补门"或"撤句"，不是挂着？
- 门凭据这句话能不能逐条指回裁决表？
- 复审只覆盖了受影响批次，没顺手放行未复审的批？
