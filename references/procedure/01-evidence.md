# 步骤 01 · 取证：先把文本里的声称抄下来，再去碰代码

> 这一步的全部意义是**顺序**：先记下"这段话声称了什么"，再去核它。顺序颠倒，核的就不是文本，而是你脑子里那句已经被实现修正过的话。

**输入**：`00-scope.md` 的批次清单。
**产物**：`.audit/rounds/{YYYY-MM-DD}-{slug}/01-evidence-B{n}.md`，每批一份。

## 产物是证据单，不是"打包送审"

不装配"每批一份自足输入"的包：裁决就在本会话里做，包是给自己看的，复制一份给自己读没有意义。

**但污染这个敌人还在。**你会不自觉地用已知的实现去理解一句话——"这句我知道它在说什么"。防线从"隔离一个陌生上下文"换成了**可查的顺序**：先记下文本声称了什么，再去核对。顺序错了，核的就不是文本，而是你脑子里那句已经被实现修正过的话。

因此本步骤的产物是**证据单**：它记录你从文本里读出了什么、机器给了什么、你据此要核什么。格式见 `references/verdict-format.md`。

## 做什么（顺序不可调换）

### 第一段：只读文本（此时禁止打开实现）

1. **通读本批全部文件，逐句过判据**，只看宪章，不看源码。逐条记：
   - `future`／`process`／`quality` 三类声称——抽出来即违规候选（红线 6／2／9），**当场就能判**，不需要任何实现证据；
   - `behavior`／`boundary`／`version` 三类——记下它在说**哪个符号**、**什么量**，待第二段核；
   - 主语链：每句的施动者能否从语法直接确定；
   - 词表召回：`node scripts/redline-check.mjs <本批文件>`，命中逐条记下，第二段再裁真假。

2. **写 `claims.json`**（按 `references/claim-extraction-spec.md`）：

   ```bash
   node scripts/graph-audit.mjs ingest-claims --root <仓> --in claims.json
   ```

   **这一步写完，本轮任何 `queue`／`record` 输出都还没出现**——这就是顺序可查的凭据。

### 第二段：核实现（声称已经落盘，才能开代码）

3. **跑图排队**：

   ```bash
   node scripts/graph-audit.mjs queue --root <仓>
   ```

   把"声称的量"与"函数体里的量"并列。**图给的是线索，不是裁决**——量对不上也可能是你读错（同名函数、分支差异），每条都要打开原文确认。

4. **逐条核量并记下证据**：量对上了记哪一行、哪个值；对不上记实测值。核完写 `01-evidence-B{n}.md` 的"量对照"表。判四值与记回图放到步骤 02。

5. **两类必须人读的核查**（机器替不了，因为它要"对着实现读文本"）：
   - **术语对表**：文本里的名词逐个对术语表核，撞既有术语或用了没登记的新词＝违规；
   - **承诺句对签名**：每条"这个工具会 X"打开签名核（红线 10）。**不核就是放行无据宣称**。

## 证据单要装什么

| 节 | 内容 | 谁产生 |
|---|---|---|
| 一、只读文本所得 | 逐条声称（含 kind／targets／quantities）、主语链命中、词表命中 | 你，第一段 |
| 二、量对照 | 每条待核声称 → 图给的量 vs 实测的量，附行号 | 你，第二段 |
| 三、两类人读核查 | 术语项与承诺句项，逐项出结果 | 你，第二段 |
| 四、留白 | 本批没核到的（读不懂、够不着）——原样记下，别猜 | 你 |

**禁止装进证据单的东西**：裁决结论（那是 02 的事）、对其他批次的判断（会诱导跨批合并）、你对自己写法的辩护（辩护即预设立场）。

## 注释体文件：核注释与字符串，不核代码骨架

CSS/SCSS/Less、纯配置文件里，面向读者的文字是**注释**，不是 `display:flex`。实测一个样式库：7 个 CSS 文件共 39,881 字节，其中注释 12,970 字节（32%）——68% 对读者是零信息。

这类文件按下面取：

- **注释全文**逐字读（含 `/* */`、`//`），保留原行号；
- **字符串字面量**（`content:`、模板文案）逐字读；
- **代码骨架**可跳读，但在证据单里标出跳过范围（如 `L120–L340 为规则体，本批略，判据只在注释里`）。

**保守起见也可以全读**，但要标出"本批判断对象是第 N–M 行注释"——不标而囫囵读，等于把找文字的成本摊进判断里。

## 检查点

- `claims.json` 的写入时间早于任何 `queue`／`record` 输出？（**唯一的顺序凭据**）
- 每条待核声称都有 targets 与 quantities？抽不出量的是真没有量，还是没读细？
- 量对照表里每行都有实测值和来源行号？没有的进了"留白"节？
- 术语项与承诺句项逐条出了结果，不是一句"已核"带过？
