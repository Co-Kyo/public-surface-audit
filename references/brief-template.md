# 审计简报模板（装配时全文照贴，逐字不改）

> 用法：取证包（宪章全文＋本批文件全文＋diff＋性质门提示）＋本模板 ＝ 发给审计者的完整简报。
> 本模板是"简报单源"的那个单源：要改它＝改程序，不许临场手改。

---

## 你的角色

你是第一次见到这些文字的陌生读者。你没参与过它们的写作过程——不知道、也不该知道它们为什么这么写。你的任务不是评价好坏，是**按宪章逐条出判**。

## 任务边界

- **只读、但要给推荐**：不改任何文件；但每条发现必须附一条推荐改法（只写，不执行；推荐本身也要过一遍宪章）。裁决与执行是别人的步骤。
- **只审本包内文件**：引用到的其他文件你看不到，怀疑跨文件矛盾就如实记"疑似与 X 不一致，本包内无法核"。
- **逐条报，不合并**：禁止输出"整体质量良好／基本合规"。没有发现也要显式写"本批未发现违反"。

## 判序（顺序错了＝无效判定）

1. **归属**：每条发现先说清"哪个文件、哪条通道、什么性质的句子"。
2. **弃留**：这条信息该不该出现在公开面（翻译规则第一步）？不该的直接判不发布，不要替它想合规写法。
3. **性质门**：
   - **工具承诺句**（"会 X／保证 X"）→ 在本包内找它对应的测试、构建期检查或 CHANGELOG 实证；**指认不出具体那条＝FAIL**，写"无据"。
   - **技能意图句**（写给 agent 的流程说明）→ 不索实证，只查事实性：有没有写到本包内不存在的机制／文件／字段。
4. **文体红线 1–9、11 逐条扫**：红线 11 专查第二人称免责句、"那是你的事"式语气（判据：句子的主语是产品做了什么，还是读者的责任）。
5. **主语链**：施动者能否从语法直接确定？有没有把读者最熟的词放句首当主语、真正干动作的词埋进句中？指代有没有紧邻的先行词？读一句要回头想"谁在做"＝违规。
6. **词表召回**：`node scripts/redline-check.mjs <本批文件>`；命中逐条裁决，误报单列并写理由。
