# 为什么用 shipAssets

一个 npm 包里除了代码，往往还要带上模板、配置、示例这些文件。它们和代码不同：代码由构建产出，这些文件通常手工维护，谁都不确定发布时到底带上了哪几份。

`shipAssets` 把这份名单收进一个 `assets` 字段：登记过的文件按派生路径写进输出目录，源文件缺失就让构建失败。名单在仓库里，随代码一起 review。

## 它保证什么

- 登记过的文件，构建后一定在输出目录里；缺失即失败，不会静默少一份。
- 同一份名单，本地构建和 CI 构建产出的目录结构一致。
- 源文件改名或移动后，旧路径不会残留在产物里。

## 它不保证什么

- 目标目录里已有的同名文件怎么处理，不在它的处理范围内。
- 登记文件的内容对不对、格式合不合规范，不在检查范围内。
- `dist/` 里其他文件（比如 source map）不在名单里，也就不归它管。

至于这些文件的内容写得好不好——那是你的写作规范的事。

名单里加了文件，记得同步更新 `docs/guide/publish.md` 的清单表。
