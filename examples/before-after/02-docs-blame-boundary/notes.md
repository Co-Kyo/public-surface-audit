# 02 · 推责式划界（红线 11）

**通道**：二·公开文档站（手写页面 `docs/guide/why.md`）
**场景**：一页"为什么用这个工具"，末尾一节"它不保证什么"。

## 违反哪条

红线 11「推责式划界」：`before.md:20`。

> 至于这些文件的内容写得好不好——那是你的写作规范的事。

## 一句为什么

破折号后半句把主语换成"你的写作规范"，边界照样说清了，但读者记下的是被推开：他读完这句，不知道自己拿到了什么，只知道有一件事归他。红线 11 要的是同一分界的中立写法——主语落在产品做了什么，或者落在读者手里多了什么。

## 改动范围

只动 `before.md:20` 一行、一个分句（27 字 → 25 字）：

| | 文本 |
|---|---|
| 前 | 至于这些文件的内容写得好不好——那是你的写作规范的事。 |
| 后 | 这些文件写得好不好，你第一次有了能单独检查的对象。 |

`before.md:2`–`before.md:19`、`before.md:22` 逐字不动。

**为什么这么改而不是删掉**：`before.md:14`–`before.md:18` 已经列了"不保证什么"三条，第 20 行不是重复的免责声明，它补的是"那不保证的部分，读者能拿它做什么"。删掉会丢一层信息；把主语从"你的写作规范"换成"你手上多出来的那个对象"，分界保留、责任不再外推。

## 同批放行的句子

- `before.md:16`「目标目录里已有的同名文件怎么处理，不在它的处理范围内」：边界声明，主语是文件与处理范围，不是读者责任——成品第三种（边界声明）的合法形态，放行。
- `before.md:18`「`dist/` 里其他文件……也就不归它管」：同上，放行。

这两句是红线 11 的对照面：**写边界合法，把边界说成"这事归你"才违规**。判据是句子的主语，不是有没有出现"不"字。

## 行号口径

`before.md` 第 1 行是 `<!-- redline-ok-file -->` 指令行，`after.md` 没有，故 `after.md` 正文整体上移 1 行：`before.md:20` 对应 `after.md:19`。
